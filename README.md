## Detailed Study Notes

### FortiAnalyzer Architecture

Understand FortiAnalyzer's role as a centralized platform for collecting, storing, analyzing, and reporting security information generated by Fortinet devices.

A typical workflow is:

**FortiGate/other device → Log collection → FortiAnalyzer storage → Search/analysis → Events/reports**

### ADOMs

Administrative Domains (ADOMs) help organize and separate devices and their logs.

Understand why organizations use ADOMs for:

- Administrative separation
- Device organization
- Multi-tenant environments
- Delegated administration
- Log management

### Log Management

Know the difference between receiving logs and making those logs operationally useful.

A good investigation should move from:

**Raw log → Filter → Correlate → Analyze → Determine significance → Document findings**

Practice searching by:

- Source
- Destination
- IP address
- User
- Timestamp
- Event type
- Severity
- Device

### Reports and Datasets

Understand how datasets provide the underlying information used to build reports.

Learn how filters, charts, report templates, and scheduling work together to produce recurring security reports.

### Security Monitoring

Use centralized logs to investigate abnormal activity such as:

- Repeated authentication failures
- Suspicious traffic
- Malware-related events
- Policy violations
- Unusual administrative activity
- Repeated security alerts

Do not rely on a single log entry when investigating an incident. Correlate related events and timestamps.
